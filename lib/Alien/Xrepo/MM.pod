=head1 NAME

Alien::Xrepo::MM - the ExtUtils::MakeMaker integration for Alien::Xrepo

=head1 SYNOPSIS

  # Makefile.PL
  use v5.40;
  use strict;
  use warnings;
  use Alien::Xrepo::MM;

  Alien::Xrepo::MM->new(
      module_name        => 'Exotic::Raylib6',
      dist_abstract      => 'Build & install raylib 6 via xrepo',
      dist_author        => 'Sanko Robinson',
      dist_version       => '0.001',
      license            => 'zlib',
      requires           => { 'perl' => 'v5.40.0', 'Alien::Xrepo::Runtime' => 0 },
      configure_requires => { 'Alien::Xrepo::MM' => 0 }
  )->Write;

And the Exotic::Raylib6 class declares its C<recipe()> once:

  class Exotic::Raylib6 : isa(Alien::Xrepo::Runtime) {
      method recipe {
          return { name => 'Exotic-Raylib6', packages => [ { name => 'raylib' } ] };
      }
  }

=head1 DESCRIPTION

Alien::Xrepo::MM is the ExtUtils::MakeMaker sibling of L<Alien::Xrepo::MB>. Dist authors who build with C<make> instead
of C<./Build> swap the build tool, nothing else: the recipe is still declared once in the dist's module, the hermetic
C<xrepo-snapshot.json> still lands in F<blib/lib/auto/share/dist/>, and C<make install> relocates it because
ExtUtils::MakeMaker copies the whole of F<blib/lib>.

C<Write()> does what L<ExtUtils::MakeMaker/WriteMakefile> does (the arguments are translated the same way
Alien::Xrepo::MB maps its properties), then adds a C<pure_all> dependency. Every C<make> therefore runs a tiny perl
freshness check; the xrepo pipeline only (re)runs when the snapshot is missing or older than the recipe inputs
(F<Makefile.PL>, F<lib/C<module>.pm>, the loaded engine modules, and any local F<recipes/> tree).

=head1 METHODS

=head2 new

  my $mm = Alien::Xrepo::MM->new(
      module_name         => 'Alien::Foo',
      # all of these are optional
      dist_abstract       => '...',
      dist_author         => 'Your Name',
      dist_version        => '0.001',
      license             => 'artistic_2',
      requires            => { ... },
      configure_requires  => { ... },
      build_requires      => { ... },
      test_requires       => { ... },
      xrepo_snapshot      => '...',   # override the derived snapshot path
      xrepo_share_dir     => '...',   # override the shallow-install root
      xrepo_cache         => 0,       # bypass the engine's on-disk cache
      xrepo_update_repo   => 1        # refresh xrepo's repository index once
                                      #   and retry a failing install
  );

Properties mean the same as they do in L<Alien::Xrepo::MB>: C<xrepo_snapshot> defaults to
F<blib/lib/auto/share/dist/<Dist>/xrepo-snapshot.json>, C<xrepo_share_dir> defaults to the snapshot's directory,
C<xrepo_cache> defaults to 0, and C<xrepo_update_repo> defaults to 0.

=head2 Write

Writes F<Makefile> (and F<xrepo-mm.json>, read by C<make>) in the current directory. Called from F<Makefile.PL>.

=head1 CONFIG FILE

C<Write()> serializes F<xrepo-mm.json> next to F<Makefile.PL>. It is how the C<make> hook knows the module name,
snapshot path, share dir, cache flag, and the C<update_repo> toggle without shell quoting.  C<make realclean> removes
it (it is in the C<clean> FILES).  It never ships in the dist: add it to F<MANIFEST.SKIP>.

=head1 ALIEN::XREPO::MM::RUN

  # invoked by the injected pure_all hook
  perl -Ilib -MAlien::Xrepo::MM -e "Alien::Xrepo::MM::run('xrepo-mm.json')"

Re-reads the config, rebuilds the snapshot when stale, and prints nothing worth worrying about when everything is
current. If the config file is absent it skips quietly so a build that merely loaded the module is unharmed.
